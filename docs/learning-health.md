# 学習の状態：何を表示し、何を判断しないか

左サイドバーの「学習の状態」を開きます。既存の日記入力、左右スワイプ、
出力のマスク、7日間のモデル復元は変更していません。

## 3つの独立した観測
- 学習処理：直近7日のジョブ結果と、全期間の現在の待機・実行数。失敗は旧モデルの
  継続と区別。初期状態を「正常に学習した」とは表示しません。
- 過去の文章の保持：最後の公開済み学習更新における、同じ学習済み資料の更新前後Loss。
  ページ数、トークン数（API）、観測日時を保持。「誤差増加を観測」は忘却の確証ではありません。
- 未学習文への汎化：独立した検証データが未構成なので **未評価**。単一の健康度/知能スコアはありません。

初回投入前Lossは現在の分岐の直近7日・最新200更新から取得し、点だけで描画します。
異なるページの値を線で結んで成長と見せません。初回投入は完全一致ハッシュとページIDの
判定で、類似文章や部分重複は検出していません。更新ごとの表は最新20件です。
対象ページLossと過去資料のLossは分けて表示。単位はnats/target-token（バイトとEOS）です。

投入・復習の提示トークン数は反復を含む現在の分岐の記録。新規の独立した情報量ではありません。
旧チェックポイントに値がない場合は未計測、途中からの計測ならその範囲だけと表示します。
処理時間はモデル読込・評価・更新で、チェックポイント保存時間は含みません。
プロセスCPU時間をPC全体の使用率やリアルタイムCPUメーターに変換しません。

## 実装
GET `/api/learning-health` → `health.summarize_health(store)`。学習エンジン本体は変更しません。
一つのread-only SQLiteトランザクションで親関係と観測を取得。モデルの重みのロード・
再評価・再学習はしません。学習ロックを取得しないため、更新中にも読めます。
ページ移動時に未保存本文があれば、既存と同じ保存処理は行いますが学習には投入しません。

親関係は `parent_id` だけをたどり、復元前の `previous_id` 側を学習成績へ混ぜません。
読み込みエラーでは前回値であることを示し、取得時刻を更新せず、表示を薄くします。
欠測/非有限/不正な旧メトリクスを架空の0へ変換しません。

復元候補数は保存メタデータ上の数です。現用ファイルの存在は確認しますが、画面を開くたびの
全チェックポイントのハッシュ検証は行いません。実際の復元時には既存エンジンが検証します。
学習履歴へのボタンは既存復元操作への移動だけで、自動復元や自動学習はしません。

## 保守・評価
純粋な表示JS/CSS、既存FastAPI、SQLite/PyTorchを使用。CDN、外部フォント、テレメトリーなし。
空/旧版/失敗/途中処理/分岐復元/削除による無効化/オフラインをテスト対象にします。
将来の独立評価セット導入には新しい評価プロトコルが必要で、今回の画面だけでは判断できません。
